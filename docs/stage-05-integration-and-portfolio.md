# 阶段五：集成、AI 内容接入与作品集（第 9–10 周）

## 本阶段目标

把前四阶段的成果合成一个可演示的“结构化关卡生产与动态加载”项目。预计投入 16–20 小时。它要展示岗位要求中的引擎理解、编辑器自动化、资源管线和动态内容承载能力。

## 依赖与源码复查

- [阶段一](stage-01-engine-and-scene.md)：场景激活与组件生命周期。
- [阶段二](stage-02-assets-and-runtime.md)：Bundle 加载、缓存与释放。复查 [CCDirector.js](../2.4.15/resources/engine/cocos2d/core/CCDirector.js) 和 [releaseManager.js](../2.4.15/resources/engine/cocos2d/core/asset-manager/releaseManager.js)。
- [阶段三](stage-03-editor-automation.md)：关卡描述格式、校验和编辑器导入。
- [阶段四](stage-04-native-and-rendering.md)：性能观察与平台边界。

## 第 9 周：打通完整流程

1. 用阶段三定义的同一份 Schema 表示两个关卡。保留 `schemaVersion` 与生成版本号；输入可手写，也可由 AI 工具生成，但必须经过相同的校验。
2. 在编辑器中预览变更、校验资源引用并导入，随后构建对应 Bundle。
3. 运行时按版本加载关卡或局部内容，展示当前版本、加载状态及错误信息。
4. 先在临时对象或待切换场景中完成加载与验证，成功后才替换当前内容；失败则继续保留上一版。

## 第 10 周：验证与展示

1. 运行成功导入、重复导入、缺字段、资源缺失、加载失败和版本回退六种情形。
2. A/B 关卡至少切换 20 次，记录资源与内存观察；复核持久引用和旧场景资源的释放。
3. 整理 README：环境、启动方式、操作步骤、数据格式、架构图、关键源码依据和已知限制。
4. 录一段短演示：输入描述 → 编辑器处理 → 构建/运行 → 动态切换 → 故障回退。
5. 准备一页求职说明：自己改了什么、为何这样设计、测到什么、还有什么尚未验证。

## 交付与完成标准

- 同一份输入能稳定生成相同场景；重复执行不产生重复节点或悬空引用。
- 校验或加载失败时，错误可定位，原场景仍可使用。
- 至少两个关卡或资源版本可切换；有首次加载、缓存、释放和回退记录。
- 有演示项目、README、架构图、测试记录与录屏；至少一项性能或内存数据注明测量方法。

## 岗位版本差异的下一步

这份学习材料基于 Creator 2.4.15。岗位提到的 PinK 编辑器与 WebGPU、Vulkan、Metal，应在完成作品后使用目标岗位实际采用的版本和文档做差异学习；不要直接把 2.4.15 的接口和渲染实现当成这些系统的实现。AI 工具可以更换，但生成结果必须继续遵守本项目的数据格式、校验与回退机制。
